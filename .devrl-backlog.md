# .devrl-backlog — 2chain continuous-improvement loop

Loop brief (Keith, 2026-06-10): "Agent tool reliability (= 2chain, doubled
down). Agents fail silently when tool schemas drift, APIs change, or outputs
violate contracts. Nobody has the 'CI for agent tools' layer yet. The
skeleton exists."

Decomposition basis: contracts already enforce on every call (`call.ts`, ajv,
circuit_broken); reliability_score is computed ONCE at publish time
(`applyKindEval.ts` pass_rate) and never re-verified — a tool that rots after
publish is only caught when a user's agent eats the failure live. STRATEGY.md
names the missing third primitive verbatim: "CI layer — every tool change
triggers an eval suite... continuously re-ranks tools." PRD guardrails
respected: no billing/marketplace (IS-NOT 3/4), no external eval framework
(IS-NOT 6 — we extend 2chain's OWN inline evals), offline-capable (IS-NOT 5).
Per CLAUDE.md Update Triggers each episode updates PRD + (if a new service
boundary) ARCHITECTURE + writes docs/plans/<date>-*.md at its plan stage.

## Queue (ordered)

### E1. Scheduled re-verification engine (the CI core)
A `reverify` service + CLI: re-run each active tool's publish-time eval suite
on demand (`2chain reverify [--tool X]`) and on an interval, persisting per-run
results to a `verification_runs` time series (storage-interface only, both
backends). Failures interact with the existing reliability gate/circuit
breaker so the REGISTRY catches rot, not the user's agent.
- Benefit: broken tools are caught proactively by the registry instead of
  reactively by a failing agent call - the core "CI for agent tools" promise.
- Falsifiable acceptance: break a fixture tool's stub output → next reverify
  run records a failed verification_run AND the tool drops below the 0.80
  gate (excluded from discover); restore the stub → runs record clean.

### E2. Evidence-driven reliability lifecycle (decay + recovery)
reliability_score becomes a recency-weighted blend of publish-time evals,
reverify history, and live call outcomes; circuit_broken tools get an
automatic re-probe path back to active (today circuit-broken is a dead end).
E1 carry-ins: (a) E2 must NOT assume byte-identical floats across the two
write paths (push JSON.stringify vs reverify json_set, ~15-sig-digit REAL);
(b) tolerate or transact the insertEvalRun->recordEvalOutcome orphan window;
(c) direct tests for eaa0501 behaviors (strict CLI args, coalesced rerank,
isSweepInFlight suppression); (d) containment catch should log diagnostics;
(e) name-only truncation partial for multi-version names past cap.
- Benefit: scores reflect CURRENT trustworthiness; transient upstream outages
  do not permanently kill good tools.
- Falsifiable: N consecutive clean reverifies restore a circuit_broken
  fixture to active; an intermittently failing fixture scores strictly lower
  than a consistently clean one.

### E3. Contract drift detection on /push
Diff new vs prior contract at /push: classify breaking vs compatible
(removed/retyped fields, narrowed enums vs additive), persist drift events,
require explicit version semantics for breaking pushes.
- Benefit: schema drift - the thesis's headline failure mode - becomes a
  recorded, classified event instead of a silent break.
- Falsifiable: pushing an output contract that retypes a field flags
  `breaking` naming the exact JSON path; an additive optional field flags
  `compatible`.

### E4. Tool health surface (API + CLI + dashboard panel)
`GET /v1/tools/:name/health` + `2chain health`: score history, last-verified
timestamp, open drift events, verification streak. Dashboard panel via the
existing SSE feed.
- Benefit: one place to answer "can I trust this tool right now?" - the
  operator-facing CI dashboard.
- Falsifiable: seeded verification + drift history renders exactly in API
  JSON and CLI table; SSE updates without polling.

### E5. Freshness in agent-facing discovery
discover_tools MCP results carry last_verified_at + verification streak so
AGENTS can weigh staleness at selection time.
- Benefit: the agent itself - not just the human - can prefer recently-vetted
  tools; closes the loop back to retrieval ranking.
- Falsifiable: two equal-score fixtures, one stale-unverified - the verified
  one ranks above it under the documented freshness term; MCP payload schema
  documented + tested.

### E6. Close the import-channel drift bypass (from E3 plan review)
Importers (src/import/*.ts) + scripts/seed-fixtures.ts call upsertTool
directly, never push() - re-imports at hardcoded version '1.0' hit the
UPDATE branch and silently REPLACE contracts, bypassing E3's drift gate
entirely. Needs its own design (imports are bulk + unowned; maybe
record-only drift events rather than gating).
- Benefit: the headline "silent drift" channel is closed for scraped/
  imported tools, not just author pushes.
- Falsifiable: re-importing a catalog tool whose contract changed records a
  drift event; the old silent-replace path no longer exists.
